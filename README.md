# ترجمه PDF فنی به Word با حفظ چیدمان (Layout-Preserving)

این نسخه متن PDFهای فنی (دیتاشیت، Reference Manual، کتاب مهندسی) را به فارسی ترجمه می‌کند و
یک فایل Word می‌سازد که **چیدمان آن شبیه همان سند ورودی** است:

- **پاراگراف‌ها** در همان جای قبلی خودشان می‌مانند؛ ترتیب و گروه‌بندی متن مثل PDF ورودی است و هر پاراگراف
  راست‌چین (RTL) می‌شود.
- **شکل‌ها و دیاگرام‌ها عیناً** از ورودی به خروجی کپی می‌شوند: هر ناحیه‌ی برداری/تصویری به‌صورت یک تصویر
  با رزولوشن بالا (پیش‌فرض 240dpi) رندر و دقیقاً در همان محل صفحه قرار داده می‌شود، بنابراین بلوک‌دیاگرام‌ها،
  تای밍‌دیاگرام‌ها و لوگوها بدون هیچ به‌هم‌ریختگی منتقل می‌شوند (متن و برچسب‌های داخل کادر شکل هم جزئی از خود
  تصویر هستند و دست‌نخورده می‌مانند).
- **جدول‌ها به‌صورت جدول واقعی Word** بازسازی می‌شوند و محتوای خانه‌های آن‌ها ترجمه می‌شود؛ حاشیه‌ها،
  ادغام خانه‌ها و عرض ستون‌ها حفظ می‌شود و ارتفاع سطرها به‌صورت خودکار باز می‌شود تا متن فارسی بریده نشود.
- سربرگ/پابرگ تکراری فقط یک‌بار ترجمه می‌شود و در همه صفحات یکسان قرار می‌گیرد؛ شماره صفحات دست‌نخورده می‌ماند.
- فونت‌های subset داخلی PDF (مثل CIDFont+F1) با فونت قابل تنظیم جایگزین می‌شوند تا حروف فارسی درست نمایش
  داده شوند (پیش‌فرض Calibri؛ می‌توانید مثلاً `B Nazanin` یا `Vazirmatn` تنظیم کنید).

## مسیر پردازش

1. `pdf_layout.py` ناحیه‌های شکل (بردارها/تصاویر) را در هر صفحه پیدا می‌کند، آن‌ها را به PNG رندر می‌کند و
   بردارها و متنِ داخل همان ناحیه را از PDF حذف و تصویر را جایگزین می‌کند. جدول‌های واقعی (۳ سطر به بالا)
   دست‌نخورده می‌مانند تا قابل ترجمه باشند.
2. `pdf2docx` سند پیش‌پردازش‌شده را به یک اسکلت Word تبدیل می‌کند (پاراگراف‌ها، جدول‌ها، تصاویر inline و
   بخش‌بندی صفحه‌ها).
3. `docx_layout.py` تمام پاراگراف‌های قابل ترجمه (بدنه + خانه‌های جدول) را به ترتیب خواندن جمع می‌کند.
4. موتور ترجمه‌ی قبلی (واژه‌نامه، محافظت از شناسه‌های فنی، batch و retry و checkpoint) بدون تغییر استفاده
   می‌شود؛ متن ترجمه‌شده داخل همان پاراگراف قبلی نوشته می‌شود و پاراگراف RTL می‌شود.
5. فایل Word نهایی ذخیره می‌شود.

## نصب

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
copy config.example.json config.json
```

کلید API را مثل قبل در متغیر محیطی مربوطه (مثلاً `WINKAPI_API_KEY`) بگذارید.

## استفاده

```powershell
# فقط بررسی اسکلت (بدون فراخوانی API): فایل موقت .layout.docx ساخته و فهرست پاراگراف‌ها چاپ می‌شود
python translate_document.py "datasheet.pdf" --dry-run

# ترجمه کامل با حفظ چیدمان
python translate_document.py "datasheet.pdf" -o "datasheet_fa.docx"

# فقط بخشی از صفحه‌ها
python translate_document.py "datasheet.pdf" -o "part_fa.docx" --pages 1-10

# ادامه از checkpoint
python translate_document.py "datasheet.pdf" -o "datasheet_fa.docx" --resume

# حالت قدیمی (متن ساده بدون شکل و جدول) اگر لازم شد
python translate_document.py "datasheet.pdf" -o "datasheet_fa.docx" --plain
```

ورودی DOCX هم پشتیبانی می‌شود: پاراگراف‌ها و جدول‌های خودِ فایل Docx در جا ترجمه می‌شوند و تصاویرش
حفظ می‌شوند.

## تنظیمات جدید (بخش `layout` در config.json)

| کلید | معنی | پیش‌فرض |
|---|---|---|
| `figure_dpi` | رزولوشن رندر شکل‌ها | 240 |
| `cluster_tolerance` / `figure_merge_tolerance` | حساسیت تشخیص نواحی شکل | 6 / 26 |
| `rasterize_logos` | تبدیل لوگوهای برداری به تصویر | true |
| `parse_stream_table` | بازسازی متن‌های ستونی/لیست‌ها به‌صورت جدول | true |
| `latin_font` / `persian_font` | فونت متن لاتین و فارسی خروجی | Calibri |

بخش `translation` هم یک کلید جدید اختیاری دارد:

- `cache_file`: مسیر یک فایل JSON به شکل `{متن انگلیسی: ترجمه}`. پاراگراف‌هایی که قبلاً (در همین سند یا
  سند دیگر) ترجمه شده‌اند دیگر به API فرستاده نمی‌شوند و ترجمه‌های جدید هم به همان فایل اضافه می‌شوند.
  با `tools/build_text_cache.py` می‌توانید ترجمه‌های checkpointهای قدیمی را به این کش تبدیل کنید:

```powershell
python tools/build_text_cache.py SAI_fa.docx.checkpoint.json cache.json --pdf SAI.pdf
```

## آزمایش بدون API

```powershell
python tests/test_layout_pipeline.py
```

با یک provider ساختگی، کل مسیر (تشخیص شکل‌ها → raster → pdf2docx → ترجمه در جا → DOCX) روی `SAI.pdf`
اجرا و ساختار خروجی (تصویرها، جدول‌ها، RTL، فونت‌ها) بررسی می‌شود.

## نمونه خروجی

`SAI_fa_layout.docx` نمونه‌ای از خروجی همین مسیر روی `SAI.pdf` است که با ترجمه‌های کش‌شده (بدون API)
ساخته شده؛ بخشی از خانه‌های جدول که در کش نبوده‌اند انگلیسی مانده‌اند ولی چیدمان، شکل‌ها و جدول‌ها دقیقاً
مثل ورودی هستند.

## محدودیت‌ها

- PDF اسکن‌شده (بدون متن قابل انتخاب) همچنان OCR نمی‌شود.
- عنوانِ داخل کادر شکل (مثلاً «Figure 283») جزئی از تصویر شکل است و ترجمه نمی‌شود؛ عنوان‌های بیرون کادر
  ترجمه می‌شوند.
- در جدول‌هایی که متن فارسی خیلی بلندتر از متن اصلی است، ارتفاع سطر باز می‌شود و ممکن است صفحه کمی طولانی‌تر
  از اصل شود؛ این برای جلوگیری از بریده‌شدن متن ضروری است.
